# formal/ — model checking for this repo

Quint specs of this repo's load-bearing state machines, checked by the Apalache
symbolic model checker, gated by a mutation proof.

```bash
node formal/bin/formal.mjs quick     # typecheck + simulate — seconds
node formal/bin/formal.mjs check     # the full gate — what CI runs
node formal/bin/formal.mjs ground X  # re-assert that model X describes the code
```

Needs Node ≥18 and a JVM 17+ (`brew install openjdk@17`; export `JAVA_HOME`).
Quint version is pinned in `quint.lock.json`; Apalache is fetched automatically into `~/.quint`.

---

## The three things this harness enforces

Most "we formally verified it" claims fail on one of these. All three are gates here.

**1. The model must be able to fail.** Every model ships a `*.mutations.json`
declaring the bugs it claims to catch. Each mutation is applied and the named
invariant must be **violated**. A mutation that passes means the model cannot see
that bug — and every clean run for that bug class is worthless. A mutation whose
patch no longer applies is also a failure, not a skip: it means the model moved
and the proof silently stopped testing anything.

> This is not hypothetical. Both of this fleet's first two models passed clean and
> then **failed their own mutation proof** — in each case on the exact bug class
> they were written for. See `docs/` for the write-up.

**2. The model must still describe the code.** `grounds.sources` names the files
the model was read from, with a content hash. When one changes, the check FAILS.
The fix is to re-read the code, correct the model, and run `formal ground <model>`
— which stamps a new hash and a date. That commit is a human asserting agreement.

The hash proves nothing about agreement. It proves someone looked. That is the
only part of model-vs-code agreement a machine can enforce, and it is worth more
than the nothing you get by default.

**3. Every result carries its bound.** A clean `verify` means *no violation is
reachable within `--max-steps`* — not "safe". `REPORT.md` quotes the bound beside
every result and any claim made from it must quote it too.

## What lives here

```
formal/
  bin/formal.mjs              the runner (vendored; zero deps)
  quint.lock.json             pinned quint + apalache + JDK
  models/
    <name>.qnt                the model
    <name>.mutations.json     grounding + bounds + the mutations it must catch
  REPORT.md                   generated by `formal check` — do not hand-edit
```

## Adding a model

1. **Read the code first, not the docs.** Docs describe intent; the model must
   describe what the code does. If they disagree, model the code and say so.
2. Write `models/<name>.qnt`. State its GAPS in the file — the paths it does not
   cover — so a green run cannot be mistaken for coverage it does not have.
3. **For every guard you model, ask what would assert it.** A precondition
   constrains the transition; it does not check anything. An authority guard is
   only checkable if a ghost variable records *who* passed it. A race is only
   checkable if the interleaving is *representable* — if the state machine makes
   the race impossible by construction, the invariant is vacuous and the mutation
   will pass.
4. Write `models/<name>.mutations.json`: one mutation per bug class you claim to
   catch, each naming the invariant that must break.
5. `formal ground <name>.qnt` to stamp the sources.
6. `formal check`. If a mutation passes, **the model is wrong, not the code.**
7. Add the grounded source paths to `.github/workflows/formal.yml` `paths:`.

## When a check finds something

The output you want is the **counterexample**, not the failure message:

```bash
quint verify formal/models/<name>.qnt --invariant=<inv> --out-itf=violation.itf.json
```

Then close the loop, which is the only step that makes any of this bear on the
shipped code:

1. Read the trace — which actor called what, in what order.
2. **Write it as a real test** in this repo's own suite.
3. Confirm the test **fails** against current code.
4. Fix. The test now pins that class forever.

## What this does not give you

- It does **not** prove the implementation has these properties. The model is a
  separate artifact. Only a replayed counterexample connects them.
- It says nothing beyond `--max-steps`.
- It covers only what the model contains. Read each model's GAPS.

> "The checker certifies the mathematics; keeping the mathematics and the code in
> agreement is a separate obligation." — hyperscale.rs/proof, whose method this follows.
